## Legend

**Status** (set only from evidence: a passing test that can be named, or a dated manual check):

| Status | Meaning |
| --- | --- |
| Not verified | No passing evidence yet, and nothing outside the team blocks it (usually: not implemented) |
| Partial (offline) | Some of the offline behaviour is tested and green; the row says which part is missing |
| Offline-verified | Unit, integration or browser tests exercise the requirement's offline acceptance on synthetic data or authored fixtures, and pass. Real-data acceptance is still open |
| Verified | The spec's acceptance criterion is met on real data (CI test green, or manual check logged with a date). **No row is Verified yet** |
| Blocked | Nothing meaningful can be tested until the item in *Blocked-by* is cleared |

**Blocked-by** names what is still needed to reach *Verified*, even when the row is *Offline-verified*:

| Value | Meaning |
| --- | --- |
| none | Can be fully verified in CI with synthetic data and authored fixtures |
| credits | Needs billed Meta Model API calls (claimed credits, budget guard on; see [credits runbook](../runbooks/credits-billing.md)) |
| hardware | Needs field hardware or field work: the 4 Reolink cameras, the iPhone Pro LiDAR scan, filmed scenarios with consent, the RTX 3090 with open weights, a phone for the field checks |
| DGX | Needs the DGX Spark (only phase D-1, which is off by default) |
| owner | Needs an owner decision or account action (billing page, Credit Terms, licence acceptance, deployment host) |

Tests are named by file (paths from the repo root) and, for key ones, by test function. Every name below is in `uv run pytest --collect-only -q` (or the e2e collection) on Nov 2; names the spec expects but that do not exist are marked *missing*. The Meta fixtures under `tests/fixtures/meta/` are **authored** in the wire format, not recorded from the live API (T-03 has not run), and no scenario has been filmed.
